## 使用场景

- 需要对 GitHub Trending 或 Hacker News 采集的原始数据进行深度分析
- 从大量技术动态中提炼高价值信息和趋势洞察
- 为知识库生成结构化的技术分析报告

## 执行步骤

1. **读取采集文件**：使用 Glob 查找 `knowledge/raw/` 下最新（按修改时间排序）的 JSON 采集文件，读取其内容。
2. **逐条深度分析**：对每条项目依次分析：
   - **摘要**：用不超过 50 字概括项目核心内容。
   - **技术亮点**：提炼 2-3 个具体技术亮点，每个亮点用事实数据说话（如 star 数、性能指标、支持的语言等），不使用模糊评价。
   - **评分**：按 1-10 分给出评分并附评分理由。
   - **标签建议**：给出 2-4 个推荐标签。
3. **趋势发现**：综合所有项目，总结：
   - 共同主题（至少 2 个）
   - 新概念或值得关注的信号（至少 1 个）
4. **输出 JSON**：将分析结果写入 `knowledge/analysis/tech-summary-YYYY-MM-DD.json`。

## 评分标准

| 分数 | 含义 | 说明 |
|------|------|------|
| 9-10 | 改变格局 | 可能重塑技术栈或行业生态的重大项目/理念 |
| 7-8 | 直接有帮助 | 解决实际问题，可立即使用或参考 |
| 5-6 | 值得了解 | 有亮点但暂不紧迫，保持关注 |
| 1-4 | 可略过 | 成熟领域的增量改进，信息量有限 |

## 注意事项

- 15 个项目中，评分 9-10 的项目**不超过 2 个**，确保高分含金量。
- 评分必须附带具体理由（如做了什么、数据支撑），禁止无依据评分。
- 技术亮点要用事实说话，避免"很好"、"强大"等模糊表述。
- 摘要严格控制在 50 字以内。
- 确保 `knowledge/analysis/` 目录存在，否则先创建。
